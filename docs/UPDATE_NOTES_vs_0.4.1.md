# 更新说明（0.4.1 → 0.4.2）

> **对比基线**：0.4.1 发行版（`HDR-Converter-0.4.1.exe`，2026-10-22 构建）
> **本版**：0.4.2（2026-10-27）
> **一句话**：图片链路补上「中调伽马」与「色域拓展」，CUDA 同步新算法后 4K 图片提速一个数量级，默认峰值统一 500 尼特。

---

## 一、图片新增「伽马（中调明暗）」

- 图片页新增 **伽马** 控件（0.1–2，默认 1.00）：只改亮度曲线中调，**白点与峰值不动**，不用再靠调白点/滚降间接压暗或提亮。
- **ICC（HDR PNG / HDR JPEG）与 Ultra HDR JPEG 共用同一条曲线**，两种输出观感一致。
- CLI / JSON 对应 `--image-gamma` / `imageGamma`。

## 二、ICC 输出新增 Oklab 色域拓展（默认开启）

- 转 **BT.2020 / Display P3** 时，按目标色域彩度上限做拉伸（保持色相与明度），低饱和 SDR 源不再只是"换个容器"，而是真正用上目标色域。
- 强度 0–1（默认 1）：0 = 纯色彩学转换、观感不变；1 = 尽量用满目标色域。输出为 sRGB 时自动无变化。
- **仅 ICC 路径（HDR PNG / HDR JPEG）**；Ultra HDR 不做拓展——增益图是单通道，HDR 色彩空间必须等于 SDR 主图。
- CLI / JSON 对应 `--gamut-expand` / `gamutExpand`。

## 三、CUDA 图片链路同步新算法，明显提速

- 新增内核覆盖：B 曲线 + 滚降 + 伽马、Oklab 色域拓展、输出色域矩阵、增益图（含局部镜面高光）。
- **4K 实测：ICC 471ms → 33ms（约 14.4×）；增益图 1099ms → 202ms（约 5.4×）。**
- GPU / CPU 一致性：ICC 10 组 + 增益图 5 组对比，8-bit 最大差 1（约 0.02%）；无 GPU 时照旧自动回退 CPU。

## 四、默认峰值亮度统一为 500 尼特

- 后端 / CLI / API / 视频 / Eclipsa 各入口的默认峰值统一为 **500**（此前存在 574 / 600 / 1000 等不一致的默认值），与界面默认 500 对齐。
- 同一素材从不同入口处理不再出现亮度漂移；**只改默认值，显式传参（含旧脚本）不受影响**。

## 五、工程与发行

- Electron 33.4 → **44.9**（Chromium 130 → 152），electron-builder 26.18，TypeScript 7（原生编译器），`tsconfig` 迁移到 `node16`。
- Windows 产物补全作者/版权元数据（`CompanyName = pixelllip`），`LICENSE` / `NOTICE` 随包分发。
- 类型检查门禁保持通过；开发态与打包态均通过启动冒烟。
- **代价**：安装包 125 MB → 164 MB（Electron 运行时变大）。

## 参数速查

| 参数 | 默认 | 范围 | 生效范围 |
|---|---|---|---|
| 伽马（中调明暗）`imageGamma` | 1.00 | 0.1–2 | ICC + Ultra HDR |
| 色域拓展 `gamutExpand` | 1.0 | 0–1 | 仅 ICC（png / jpg_icc） |
| 峰值亮度 | 500 | 400–1250 | 全部入口的默认值 |

## 已知限制

- Ultra HDR JPEG 不做色域拓展（结构决定，非缺陷）。
- 色域拓展与图片伽马只作用于图片链路；视频侧是「assign」语义，详见 `docs/GAMUT_IMAGE_VS_VIDEO_zh.md`。

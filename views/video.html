为什么这么估？
峰值亮度 = 预览目标渲染亮度（HLG gain / HDR 画布高光上限，拖动即改预览观感）+ 导出 max-cll（曝光/高光上限 = 峰值/白点）——预览与导出同值，调一处两端生效。默认 500 尼特
白点=视频里 SDR 白像素的绝对亮度（默认 203，基于 BT.2408 规范）；峰值亮度滑块决定高光上限/max-cll。图片预览按此校准
HDR Transfer Functions（传递函数）—— 传递函数定义视频文件数字信号值与显示线性光输出的数学关系。 标准动态范围（SDR）传统上用伽马曲线（如 sRGB / BT.1886）处理；HDR 内容由 ITU-R BT.2100 标准 确立两种主要非线性传递函数以覆盖大幅扩展的动态范围：PQ（Perceptual Quantizer，感知量化器） 与 HLG（Hybrid Log-Gamma，混合对数伽马）。深入了解这些传递函数并非使用本工具的必要条件。
自动检测：内容传递函数与色域在可能时自动检测（auto=按源色彩元数据 ffprobe 识别并自动填入）； 若检测不到，可用本区其余控件手动设置 —— 同参考项目 HDR Explorer 的行为： "The content's transfer function and color primaries are automatically detected when possible, but if not, they can be changed with the other controls in this section."
合并语义：本区选项同时决定 输入解读（预览/转换如何线性化源帧）与 输出编码（导出视频的传递函数/色域）——所见即所得，调一处两端生效 （例外：输出格式 = Eclipsa 时输出传函固定 PQ，见下方说明）。
与预览台 hdr_preview「内容区 · 传递函数」同表；同时作输入解读与输出编码（例：auto + SDR 素材 → HLG，导出为 HLG 内容；手动选 PQ → 输出 HDR10 信号）。auto：视频元数据给出 PQ/HLG 照用（ffprobe 识别 smpte2084/arib-std-b67）；SDR 内容（含未识别）默认按 HLG 解读（HLG 与 SDR 显示向后兼容）
与预览台 hdr_preview「内容区 · 色域」同表（11 种）；同时作输入解读与输出编码。auto：ffprobe 色彩元数据自动填入；SDR 内容默认 BT.709。注：输出编码对 film/XYZ/RP 431-2/CICP 22 等编码器不直接支持的色域将回退 BT.2020
输出格式 = Eclipsa：输出传函可选 PQ / HLG（两选一）——「传递函数」下拉锁定在这两个 选项（其余置灰），值即输出编码；输入解读自动跟随源（SDR 内容默认按 HLG，预览与导出一致， 不会过曝）。预览同步切到所选输出传函（PQ/HLG）导出呈现——传函只是编码方式、不改变内容 （把 SDR 素材当 PQ 码解码才会发暗/过曝，已正确移除）。色域仍可修改（P3 / BT.2020， 其余自动回退 BT.2020），元数据增益应用空间随输出色域声明（P3 → chromaticities_mode=1）。
scene：检测镜头突变处切窗，最贴合内容；无明显切镜时自动回退均分。uniform：按时间帧平均切成 N 段
越小越容易切窗（更碎）；0.4 为 ffmpeg scene 分数常用默认
更短视窗内的切点会被合并，避免碎片窗；默认 0.5s
开启后按当前分窗策略对源视频做一遍亮度统计（单遍解码，秒级），预览按 ST 2094-50 参考白配方逐窗应用 headroom（ALTR 增益曲线 + 显示 headroom 自适应，与 hdr-explorer 渲染语义一致）。分窗/传函/色域参数变更自动重算。

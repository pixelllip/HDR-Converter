# ST 2094-50 规范精读（PCD2，2026-02-23）

> 本文是对 SMPTE ST 2094-50 第二公开委员会草案（Application #5, Broadcast）的**转述式精读笔记**，
> 供本实验使用；不含原文复制。条款编号与草案一致，便于对照原文。
> 正式实现时请以最新官方版为准（见 `../reference/SOURCES.md` 版本时间线）。

## 0. 一句话定位

ST 2094-50（Application #5）定义了**一种“嵌在内容里的动态颜色体积变换元数据”**：
让操作系统 / 合成器 / 显示管线在**同一相对线性颜色空间**里，把多个 HDR 与 SDR 信源
（文字、图形、图片、视频）按各自声明的 **HDR 参考白（Reference White）** 归一后，
再按显示端可提供的 **headroom（动态范围余量）** 做自适应色调映射合成——从而跨
Web、电视、桌面得到一致、可预期的结果。它是 ST 2094-1:2016（核心组件）的一个特化应用。

## 1. 关键概念（草案第 4 章，转述）

- **HDR 参考白 `Lwhite`**（cd/m²）：把内容归一进相对线性空间的锚点；
  常取 100% 漫反射白所处亮度。**默认 203 cd/m²**（与 BT.2408-8 / ISO 21496-1 同源），
  也可显式携带自定义值。
- **相对线性颜色空间**：输出线性光 `[R,G,B]`，其中 `[1,1,1]` = 参考白。
- **HDR headroom（档）**：`H = log2(最大内容光级 / 参考白)`。
  例如参考白 203、MaxCLL 1624 → `H = log2(1624/203) = 3`，即参考白之上 3 档。
- **baseline 图像 / baseline HDR headroom `Hbaseline`**：被描述图像及它的 headroom。
- **alternate 图像 / alternate HDR headroom `Halt,i`**：第 i 张“伴随变体”
  （如 SDR 版或不同剪裁版）及它的 headroom；`Nalt` ∈ [0,4]。
- **颜色增益函数 `Gain(C)`**：把增益应用颜色空间里的一个颜色映射为**每分量 log₂ 增益**；
  `Gain = GainCurve ∘ ComponentMixing`。
- **targeted HDR headroom `Htarget`**：显示端的目标 headroom（**不随内容编码**，
  由显示端按其峰值 / 参考白显示亮度自行计算，见 A.3）。

## 2. 数据结构模型（第 6 章，转述）

- **颜色体积变换（6.1）**：参数 = `Lwhite`（须在 (0,10000]）+ 可选 `ToneMap`。
- **HATM 结构（6.2）**：参数 =
  `Hbaseline`（[0,6]）+ `Nalt`（[0,4]）+ 各 `Halt,i`（[0,6]，互不相等、递增）+
  各 `Gain_alt,i` + 增益应用色域色度 4 组 (`χred,χgreen,χblue,χwhite`)。
- **评价式（规范性）**：`ToneMap(C, Htarget) = C × 2^G`，
  其中 `G` 是把 `Htarget` 夹到 `[H0…HN-1]`（baseline + alternates 排序并插入零增益）后，
  对包围它的两个 headroom 的增益函数在 **log₂ 域**做线性加权（草案公式 2-5）。
  特殊情形：`Nalt=0` 时 `G=[0,0,0]`，即**恒等→只做显示端投影/裁剪**（B.4）。
- **颜色增益函数（6.3）**：`Gain(C) = [GCR(mr), GCR(mg), GCR(mb)]`；
  三通道同值时增益只算一次。零增益函数返回 `[0,0,0]`。
- **分量混合函数（6.4）**：`M = ComponentMixing(C)`（灰→灰保持），
  系数 `kred,kgreen,kblue,kmax,kmin,kcomponent` 各 ∈[0,1] 且和为 1；
  `fcommon = cr·kred + cg·kgreen + cb·kblue + max·kmax + min·kmin`，
  `M = [cr·kcomponent + fcommon, …]`。与 **ICC Adaptive Gain Curve** 的输入评价器同构。
- **增益曲线（6.5）**：`Ncp` 个控制点 `(x_i, y_i, m_i)`，`x∈[0,64]`、`y∈[-6,6]`、
  `Ncp≤32`、`x` 单调；段内为三次 Hermite（PCHIP 斜率可选），
  段外用钳制 + `log2` 外推（草案公式 11/12）。

## 3. 元数据集组成（7.1，转述为树）

```
ApplicationInfo(ApplicationIdentifier=5, ApplicationVersion)
TimeInterval(TimeIntervalStart, TimeIntervalDuration)
ProcessingWindow(WindowNumber=0, UpperLeft=[0,0], LowerRight=图像尺寸)
ColorVolumeTransform
├─ HdrReferenceWhite                     （恰好 1 个；默认 203）
└─ HeadroomAdaptiveToneMap               （至多 1 个；可缺省 = 仅参考白）
   ├─ BaselineHdrHeadroom
   ├─ NumAlternateImages
   ├─ GainApplicationChromaticities[8]   （RG/GG…白点，8 个色度坐标）
   └─ AlternateImage[a]                  （每个）
      ├─ AlternateHdrHeadroom[a]
      └─ ColorGainFunction[a]
         ├─ ComponentMix[a]（6 个系数）
         └─ GainCurve[a]（Ncp + 控制点(x,y,m)）
```

约束（7.2）：`ApplicationIdentifier=5`、`ApplicationVersion=0`；
窗口固定为全图（WindowNumber=0）；`HdrReferenceWhite→Lwhite`；
HATM 各参数按 6.2 约束组装。

## 4. 元数据携带（7.3，转述——本实验最关心的接入点）

- 携带方式：**可使用基于 ITU-T T.35 的机制**；
- 识别标识：**country code `0xB5`（美国）、terminal provider code `0x0090`（SMPTE）、
  terminal provider oriented code `0x0001`**；
- 载荷编码：**必须用 Annex C 的二进制编码**；
- 在“码流与容器都支持 T.35 携带”的系统里，**容器携带优先于码流携带**。

> 含义：目前草案只在“标识 + 二进制载荷”层面定死了；**具体的码流（HEVC SEI 类型）与
> 容器（MP4 盒）映射**是在既有 T.35 机制之上的组合。HEVC 侧自然的载体是
> `user_data_registered_itu_t_t35`（payload type 4）SEI；容器侧的盒映射草案未详述，
> 属待定/需注释反馈的空白点。

## 5. 二进制编码（Annex C 规范性，转述为字段表）

统一约定：`u(N)` 高位在前；≥1 字节的字段字节对齐；`u(16)` 即大端；
`reserved_zero` 必须为 0。

### 5.1 应用信息（C.2.1，共 1 字节+内容）

```
application_version          u(3)   = 0
minimum_application_version  u(3)   = 0   （遇到不认识的最小版本应丢弃整段）
reserved_zero                u(2)
smpte_st_2094_50_color_volume_transform()
```

### 5.2 颜色体积变换（C.2.2）

```
has_custom_hdr_reference_white_flag  u(1)   // 0 → 用默认 203
has_adaptive_tone_map_flag           u(1)   // 0 → 只声明参考白
reserved_zero                        u(6)
if has_custom:  hdr_reference_white  u(16)
if has_atm:     smpte_st_2094_50_adaptive_tone_map()
```

### 5.3 自适应色调映射（C.2.3）

```
baseline_hdr_headroom                u(16)   // = Hbaseline×10000
use_reference_white_tone_mapping_flag u(1)   // 1=“按 C.3.8 由参考白自动算”，0=“逐项给出”
if flag==0:
  num_alternate_images               u(3)
  gain_application_space_chromaticities_mode u(2)  // 0=709, 1=P3, 2=2020, 3=自定义(跟8个u16)
  has_common_component_mix_params_flag u(1)
  has_common_curve_params_flag        u(1)
  for a in min(num_alt,4):
    alternate_hdr_headrooms[a]        u(16)
    smpte_st_2094_50_component_mixing(a)
    smpte_st_2094_50_gain_curve(a)
else: reserved_zero                  u(7)
```

### 5.4 分量混合（C.2.4）

```
component_mixing_type[a]  u(2)   // 0=只用Max(系数Max=1) 1=只用Component(kcomponent=1)
                                // 2=R+G+B加权(16,16,16,12,…) 3=自定义6系数
if type==3:
  has_component_mixing_coefficient_flag[a][k] u(1) ×6   // 缺省系数=0
  component_mixing_coefficient[a][k]            u(16) ×6 // 归一化: p_k/Σp
```

### 5.5 增益曲线（C.2.5）

```
gain_curve_num_control_points_minus_1[a] u(5)   // 实际=Ncp-1
gain_curve_use_pchip_slope_flag[a]       u(1)   // 1=斜率走 C.3.9 计算
reserved_zero                           u(2)
x_control_points[a][c]                  u(16) ×Ncp   // =x×1000
y_control_points[a][c]                  u(16) ×Ncp   // y×10000（符号由头档高低决定）
if !pchip: theta[a][c]                  u(16) ×Ncp   // 斜率=tan((θ−18000)·π/36000)
```

### 5.6 定点语义（C.3.3–C.3.7，转述）

- `Lwhite = 默认203`，或 `clamp(u16,1,50000) ÷ 15`（**注**：PCD2 的 HTML 里该公式疑似排版错乱，
  正式版请核对 50000/15≈3333 上限与 203=3045/15 的对应关系）。
- `Hbaseline / Halt,i = min(u16,60000) ÷ 10000`（即上界 6.0）。
- 色度：模式 0/1/2 为 709/P3/2020 常量；模式 3 自定义 `= min(u16,50000)÷50000`。
- 增益曲线 x: `÷1000`（上界 64）；y: `±×÷10000`（上界 6，符号由该 alternate 相对 baseline 高低定）；
  θ 为 0~360° 刻度映射到斜率 tan。

## 6. “参考白预设配方”（C.3.8）——免人工调参的生成捷径

当 `use_reference_white_tone_mapping_flag=1`：

- 增益应用色域 = **BT.2020**；
- `Hbaseline=0` → `Nalt=0`（无色调映射）；
- `Hbaseline>0` → `Nalt=2`：
  - `Halt,0 = 0`（即 SDR 变体）；
  - `Halt,1 = log2(8/3) × min( Hbaseline / log2(1000/203), 1 )`；
- 每个 alternate：`ComponentMixMax=1`（其余 0 → 只按亮度 max 通道增益）；
- 增益曲线：`Ncp=8`，膝点 `[1, ywhite,a]`，其中
  `ywhite,0 = 1 − ½·min(Hbaseline / log2(1000/203), 1)`，`ywhite,1 = 1`；
  控制点由一条相对线性空间的二次 Bézier 处采样得到（臀部高光压缩系数 κ=0.65，
  曲线端点为 `[1,ywhite]→[2^Hbaseline, 2^Halt,a]`），再取 log₂ 得到增益曲线及其斜率（C.3/C.4/C.6）。

**工程价值**：编码端只需求出每窗 `Hbaseline`（= log2(窗口峰值/参考白)），
其余全部参数可由该配方自动合成——这让“把本项目已算出的逐窗高光信息转成
ST 2094-50 元数据”变成**有限的、确定的**工作，而不是去拟合任意曲线。
